# План: Refactor IobrokerApiService — SRP + извлечение утилит

## Проблема
`IobrokerApiService` (~550 строк) нарушает SRP:
- HTTP wrappers (getState, setState, getObject, getObjects, getStates)
- Adapter management (getAdapterList)
- Device parsing (getAdapterDevices)
- Device classification (detectDeviceTypeFromChannels — 140 строк!)
- Type mapping (mapDeviceType, mapControlType)
- Utility functions (getJsonString, parseJsonValue)
- Device name extraction (extractDeviceBaseId, extractDeviceName)

**Дубликаты:** `IobrokerRepositoryImpl` содержит копии `parseJsonValue()`, `getJsonString()`, `mapDeviceType()`, `mapControlType()`.

## Решение

```kotlin

    fun parseValue(str: String?): Any?
```

### Фаза 2: Создание сервисов

#### 2.1 IobrokerRestClient (rename IobrokerWebSocketClient)
**Файл:** переименовать `IobrokerWebSocketClient.kt` → `IobrokerRestClient.kt`

Единственное изменение — имя класса. Ответственность: HTTP/WebSocket запросы + connection management.

#### 2.2 AdapterService
**Файл:** `app/src/main/java/com/besenok/smarthome/data/remote/iobroker/AdapterService.kt`

Ответственность: работа с адаптерами ioBroker.
Методы:
- `getAdapterList(restClient): List<AdapterInfo>`
- `extractAdapterId(objId: String): String?`
- `findAdapterName(objects: JsonObject, adapterId: String): String`

Исходник: IobrokerApiService.kt:64-157

#### 2.3 DeviceParser
**Файл:** `app/src/main/java/com/besenok/smarthome/data/remote/iobroker/DeviceParser.kt`

Ответственность: парсинг устройств из JSON.
Методы:
- `parseAdapterDevices(adapterId, states, objects, restClient): List<Device>`
- `extractDeviceBaseId(stateId, adapterId): String?`
- `extractDeviceName(deviceBaseId, adapterId): String`
- `parseChannels(stateList, restClient): List<Device.Channel>`
- `parseChannel(obj: JsonObject, restClient): Device.Channel?`
- `parseStateObject(obj: JsonObject): State`

Исходник: IobrokerApiService.kt:160-246 + IobrokerRepositoryImpl.kt:300-400

#### 2.4 DeviceClassifier
**Файл:** `app/src/main/java/com/besenok/smarthome/data/remote/iobroker/DeviceClassifier.kt`

Ответственность: классификация устройств по каналам (weighted scoring).
Методы:
- `classify(channels, fallbackName): DeviceType`

Исходник: IobrokerApiService.kt:278-417 (140 строк алгоритма)

#### 2.5 IobrokerApiClient — координатор
**Файл:** `app/src/main/java/com/besenok/smarthome/data/remote/iobroker/IobrokerApiClient.kt`

Ответственность: координация сервисов, публичный API.
Зависимости (через DI):
- `restClient: IobrokerRestClient`
- `adapterService: AdapterService`
- `deviceParser: DeviceParser`
- `deviceClassifier: DeviceClassifier`
- `json: Json`

Методы (публичный интерфейс):
- `getState(objectId): IobrokerState?` — делегирует restClient
- `setState(objectId, value, ack)` — делегирует restClient
- `getObject(objectId): JsonObject?` — делегирует restClient
- `getObjects(pattern): JsonObject?` — делегирует restClient
- `getStates(pattern): JsonObject?` — делегирует restClient
- `getAdapterList(): List<AdapterInfo>` — делегирует adapterService
- `getAdapterDevices(adapterId): List<Device>` — делегирует deviceParser + deviceClassifier
