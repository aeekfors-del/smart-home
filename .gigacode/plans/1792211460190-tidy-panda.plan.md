# План разработки Android-приложения «Умный дом» (ioBroker)

## Обзор

Android-приложение на **Kotlin** с архитектурой **MVVM + Clean Architecture**, подключается к **ioBroker** через **WebSocket JSON-RPC 2.0** (порт 8081). Также получает погоду и точное время через интернет.

### Основные модули
1. **Управление устройствами** — свет, розетки, датчики (через ioBroker states)
2. **Мониторинг** — температура, влажность, безопасность (чтение из ioBroker)
3. **Сценарии и автоматизация** — правила и триггеры (через ioBroker scenario engine)
4. **Погода** — текущая погода + прогноз (OpenWeatherMap API)
5. **Точное время** — синхронизация с worldtimeapi.org

### Технические решения
- **Язык:** Kotlin
- **UI:** Jetpack Compose + Material Design 3
- **Архитектура:** MVVM + Clean Architecture (3 слоя)
- **Сеть ioBroker:** Ktor Client WebSocket (JSON-RPC 2.0)
- **Внешние API:** Ktor Client HTTP (OpenWeatherMap, worldtimeapi.org)
- **DI:** Hilt
- **Навигация:** Jetpack Navigation Compose
- **Асинхронность:** Kotlin Coroutines + Flow
- **Локальное хранилище:** DataStore (настройки) + Room (кэш)
- **Минимальный SDK:** Android 8.0 (API 26)

## Шаг 3: Data Layer — ioBroker WebSocket JSON-RPC

### 3.1 IobrokerWebSocketClient — Управление соединением

**Файл:** `data/remote/iobroker/IobrokerWebSocketClient.kt`

**Ответственности:**
1. Подключение к `ws://{host}:8081`
2. Аутентификация через JSON-RPC `authenticate`
3. Автопереподключение с экспоненциальной задержкой (1s → 30s)
4. Keep-alive (ping/pong)
5. Эмит состояний через `StateFlow<ConnectionState>`
6. Маршрутизация входящих JSON-RPC уведомлений (stateChange)

**Жизненный цикл:**
1. `connect()` → `establishConnection()` → WebSocket к `ws://{host}:8081`
2. Отправка JSON-RPC `authenticate` с username/password из DataStore
3. При успехе — сохранение session ID, эмит `Connected(sessionId)`
4. Фоновая корутина читает WebSocket input
5. Входящие сообщения маршрутизируются:
   - JSON-RPC response (с `id`) → доставляется вызывающему через `CompletableDeferred`
   - JSON-RPC notification (без `id`) → forwarding в `_incomingMessages`
6. Keep-alive корутина отправит periodic ping
7. При обрыве — `startReconnection()` с exponential backoff

### 3.2 JSON-RPC 2.0 Формат сообщений

**Request:**
```json
{"jsonrpc":"2.0","method":"getState","id":1,"params":["hm-rpc.0.LEQ0123456.1.STATE"]}
```

**Response (success):**
```json
{"jsonrpc":"2.0","result":{"val":true,"ack":false,"ts":1700000000000},"id":1}
```

**Response (error):**
```json
{"jsonrpc":"2.0","error":{"code":-32601,"message":"Method not found"},"id":1}
```

**Notification (stateChange):**
```json
{"jsonrpc":"2.0","method":"stateChange","params":{"id":"hm-rpc.0.LEQ0123456.1.STATE","state":{"val":true,"ack":false}}}
```

### 3.3 IobrokerApiService — Обёртки над RPC методами

**Файл:** `data/remote/iobroker/IobrokerApiService.kt`

| Метод | JSON-RPC | Описание |
|-------|----------|----------|
| `authenticate(user, pass)` | `authenticate` | Авторизация |
| `getObject(id)` | `getObject` | Получить объект по ID |
| `getState(id)` | `getState` | Получить состояние |
| `setState(id, value, ack)` | `setState` | Установить состояние |
| `subscribe(id)` | `subscribe` | Подписаться на обновления |
| `unsubscribe(id)` | `unsubscribe` | Отписаться |
| `enumList()` | `enum.list` | Список enum |
| `deviceList()` | `device.list` | Список устройств |
| `adapterList()` | `adapter.list` | Список адаптеров |
| `sendMessage(...)` | `message` | Отправить команду адаптеру |

**Discovery устройств:**
1. Вызов `device.list` → список device-объектов
2. Для каждого — вызов `getObject(deviceId)` → полная структура (channels + states)
3. Альтернатива: обход дерева объектов от `0_userdata.0`, `hm-rpc.0`, и т.д.

### 3.4 ioBroker DTO

**IobrokerObject:** `_id`, `type` (device/channel/state/enum), `common` (name, type, role, min, max, unit, states), `native`, `parent`, `children`

**IobrokerState:** `id`, `val` (Any — Boolean/Number/String), `ack`, `ts`, `lc`, `from`, `q`, `user`

### 3.5 Маппинг ioBroker → UI Control

| ioBroker type + role | UI Control |
|----------------------|------------|
| boolean + switch | `StateSwitch` (toggle) |
| number + states | `StateDropdown` |
| number + min/max | `StateSlider` |
| number (без min/max) | `NumberInput` |
| string + states | `StringDropdown` |

## Шаг 5: Domain Layer

### 5.1 Domain Models

**Device:** id (ioBroker object ID), name, type (LIGHT/SOCKET/SENSOR/THERMOSTAT/BLIND/OTHER), controlType, state, channels, unit, icon

**Sensor:** id, name, sensorType (TEMPERATURE/HUMIDITY/PRESSURE/LIGHT/MOTION/DOOR_WINDOW/GAS/SMOKE), value, unit, timestamp

**Scenario:** id, name, description, trigger, actions (list of state changes), enabled, lastExecuted

**WeatherInfo:** city, temperature, feelsLike, humidity, pressure, condition, description, iconCode, forecast (list)

**TimeInfo:** dateTime, timezone, timestamp, dayOfWeek

### 5.2 Repository Interfaces

```kotlin
interface IobrokerRepository {
    suspend fun connect()
    suspend fun disconnect()
    val connectionState: StateFlow<ConnectionState>
    suspend fun getDevices(): List<Device>
    suspend fun getDevice(deviceId: String): Device
    fun getStateFlow(objectId: String): StateFlow<State?>
    suspend fun setState(objectId: String, value: Any, ack: Boolean = true)
    suspend fun getSensors(): List<Sensor>
    fun getSensorValueFlow(sensorId: String): StateFlow<Any?>
    suspend fun getScenarios(): List<Scenario>
    suspend fun executeScenario(scenarioId: String)
}

interface WeatherRepository {
    suspend fun getCurrentWeather(lat: Double, lon: Double): WeatherInfo
    suspend fun getForecast(lat: Double, lon: Double): List<ForecastEntry>
}

interface TimeRepository {
    suspend fun getCurrentTime(): TimeInfo
}
```

9. **Точное время** — данные загружаются из worldtimeapi.org
10. **Автопереподключение** — при потере соединения происходит reconnect

12. **Dark mode** — корректное переключение темы
